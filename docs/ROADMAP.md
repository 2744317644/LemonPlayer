# 分步开发计划（按模块推进）

> 规则：**一次只主攻一个模块**，每步 ≤ 3 天；每步结束必须有验收路径 + CI 绿；你验收通过后再进下一步。
> 模块清单与边界见 [MODULES.md](MODULES.md)。

## 当前基线

- 最新版本：**v2.0.0**（Step 0–10 全部完成）

- 版本：**v1.1.0**（播放器 VidHub 对齐、NCOP/NCED 排除、Bangumi 中文分集标题）
- 测试：Packages 100 用例（Linux CI），UI 测试 3 条，构建/发布 CI 全绿
- 已知待验收：播放器手势/面板/锁屏、字幕显示、媒体库扫描、竖屏锁定横屏

## Step 0：模块冻结（0.5 天）

**目标**：把边界写死，后续不再"跨模块顺手改"。

- 产出：`docs/MODULES.md`、本文件
- 动作：检查现有 import 边界（Packages 不 import App；各包依赖符合图）；给新文件定归属规则
- 验收：模块图/契约/Checklist 经你确认

## Step 1：地基 M1-M3（1–2 天）✅ 已完成（2026-11-07）

**目标**：错误、日志、令牌存储三件套可诊断、可测试。

**已完成**：`LemonError` 统一错误（状态码/可重试/诊断文案）、HTTP 重试策略 + `HTTPClientConfiguration` + `RateLimiter` + 统一 UA、Bangumi 客户端接入限流、诊断页错误/警告筛选、媒体库失败写诊断日志。测试 +9（Core 5 / Network 6）。

- M1：统一 `LemonError`（网络/解析/鉴权/文件），格式化工具集中
- M2：HTTPClient 超时/重试/状态码约定；Bangumi UA/限流从 M5 下沉到 M2 的配置
- M3：Keychain 封装（access/refresh token 唯一入口），迁移现有 UserDefaults 残留
- 验收：设置→诊断页能导出"最近错误 + HTTP 状态码"；`swift test` 覆盖错误映射
- 风险：Keychain 迁移需兼容旧登录态（保留一次性回退）

## Step 2：登录 A2（2 天）✅ 已完成（2026-11-07）

**目标**：三种入口稳定，token 生命周期闭环。

**已完成**：`SessionStore.authorized` 统一 401/117 自动刷新重登；Browse/Library/Player/Settings 全部接入；冷启动刷新失败区分「登录失效」与「网络异常」（后者可重试）；Web 登录可重新加载网页；账号密码页保留并标注风控说明。

- 扫码：轮询失败重试/自动刷新二维码（已有，补充取消与超时）
- 网页登录：localStorage 捕获失败时的提示与重试；取消返回
- 账号密码：明确标注"受风控，建议网页登录"（或暂时隐藏，按你决定）
- token：`validAccessToken()` 统一刷新；401/117 自动重登一次
- 验收：冷启动恢复登录；过期后自动刷新；三种入口手动各走一遍
